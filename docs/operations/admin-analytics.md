## Refresh finite observations

The GitHub schedule uses minutes 02, 07, and every five minutes afterward. A job observes for up to 240 seconds, with a native worker at the start and about 180 seconds in, and a warehouse worker about every ten seconds when workers finish in time. Workers run sequentially and share the app's 90/minute and 900/hour query budget. A worker has at most 35 seconds plus one second to confirm termination and an 8 KiB combined output cap. The runner reserves that full slot before starting a child, including room before the next native check. It stops admitting workers before the window ends instead of starting one with a shortened timeout. The runner reports bounded status counts without worker output. A failed native worker still permits an independent warehouse attempt after it exits and leaves the run failed. Each environment lets an in-flight job finish. GitHub can delay or drop scheduled runs and pending jobs. PostHog warehouse sync runs independently with a five-minute minimum and its own completion lag. Splits, retries, query limits and job delays affect coverage. Record actual dispatch gaps, connector lag and completed sweep times in staging. [GitHub schedule](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) · [Managed source sync cadence](https://posthog.com/docs/data-pipelines/sources#sync-frequency)

Use `npm run analytics:observe -- --environment staging` for a local schedule preview. The scheduled job supplies `--run` after the repository gates. To troubleshoot a specific warehouse claim with the same access and budget, the owner can run `node scripts/refresh-admin-analytics.mjs --environment staging --source warehouse` outside an active schedule window. One invocation leases one partition for up to 30 seconds. Each leaf compares both directions for all finance fields, revisions, update timestamps, link contents and tombstones. Two source reads bracket provider reads. Overflow splits a hash prefix into all sixteen children, covering facts with the same effective time. A completed sweep records the minimum source observation among matched leaves. A changing multirow leaf can refine up to eight hash characters. Later sweeps recheck late and backdated commits. An incomplete sweep, expired lease, malformed value, missed update, quota limit or unavailable comparison cannot advance the proof.

Each native observer run reads effective retention with the paired operator credential. The documented explicit null pair means no retention period applies. Missing or inconsistent fields fail verification. The database clips coverage to the latest retained-from date, rolling retention floor and previously expired intervals. Successful retention verification expires after 24 hours. A later retention increase cannot restore an expired period. [Events retention API](https://posthog.com/docs/api/events-retention)

The observer generates opaque marker UUIDs at server time, excludes them from all visitor reports, and reads back adjacent markers with the fixed native Endpoint. A finite native query checks availability of the same interval, including intervals with zero visible behavioral events. Only a matched pair at most ten minutes apart can extend persisted observed coverage. Gaps and delayed markers remain unavailable. Reconciliation of these provider-visible observations does not certify delivery of every client submission. Reverify the separate retention capability, actual schedule, source mappings, archive/backfill coverage, API budget and end-to-end lag.
