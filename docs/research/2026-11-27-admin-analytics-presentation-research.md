# Admin analytics presentation research

27 November 2026 · Sole Sneakers

Start the redesign with the questions an operator needs to answer during a sale. The first screen should make sales, confirmed orders, measured traffic, and shopping completion easy to find, with the selected period, timezone, and coverage visible beside the numbers. A chart earns its space when a pattern, ranking, or sequence changes the operator's decision. Use a table for exact values, detailed breakdowns, and longer lists. These are recommendations for design review. [Government Analysis Function dashboard guidance](https://analysisfunction.civilservice.gov.uk/policy-store/data-visualisation-building-and-managing-dashboards/) · [ONS chart selection](https://service-manual.ons.gov.uk/data-visualisation/chart-types/choosing-a-chart-type)

## What the dashboard does today

- Overview already shows net product sales, confirmed orders, average order value, and store conversion. Its funnel uses tracked sessions and distinguishes rates from the first and previous steps. Its source ranking includes attribution coverage. Acquisition already has traffic and sales trends, so there is an existing place to look for hourly traffic. [Overview](../../src/Modules/Analytics/Source/Features/Dashboard/reports/OverviewReport.tsx) · [Acquisition](../../src/Modules/Analytics/Source/Features/Dashboard/reports/AcquisitionReport.tsx) · [Funnel query](../../src/Modules/Analytics/Source/Features/Reporting/queries/visitors.ts)
- The React SVG trend breaks lines when values are missing and exposes exact values in a disclosure table. Its plot uses bucket position and three date-only labels, and the report contract supports day, week, and month in America/New_York. Hourly traffic therefore needs both report and presentation changes. Coverage messaging already handles stale reports and partial days. Preserve those distinctions at hourly resolution. ## Hourly data and accessibility

- Distinguish visitors, sessions, and buying customers in names and descriptions. One visitor can have several sessions and may never buy. Hourly unique visitor counts cannot be added together to obtain the daily unique visitor count because a person can appear in several hours. Keep the independently calculated period total beside the trend. These definitions follow the existing distinct-visitor and session calculations. [Existing audience query](../../src/Modules/Analytics/Source/Features/Reporting/queries/visitors.ts)
- Count sessions by their entry hour under the existing consent and filter scope. Display the timezone and interval boundaries, including offsets for any repeated local hour at the daylight-saving transition. A short-range preset such as the last 24 completed hours bounds the view. If an in-progress hour is included, label it at the point and in the table. Compare equivalent elapsed windows if a comparison is offered. Confirm the hourly source and freshness behavior before publishing the chart. [Existing session query](../../src/Modules/Analytics/Source/Features/Reporting/queries/visitors.ts) · [ONS guidance on irregular and missing data](https://service-manual.ons.gov.uk/data-visualisation/chart-types/line-chart)
- Use **0** for a bucket with verified coverage and no qualifying activity. Leave a gap and label **Unavailable** when the source cannot establish the value. Show known values with a **Partial** label for incomplete intervals or incomplete coverage, with the reason visible nearby. Keep **Stale** next to the last successful timestamp when a retained report is shown. Preserve the same meaning in the plot, summary, tooltip, and table. Distinguish the requested range, report generation time, and observed source lag when the contract establishes each. [ONS line charts](https://service-manual.ons.gov.uk/data-visualisation/chart-types/line-chart) · [Existing coverage UI](../../src/Modules/Analytics/Source/Features/Dashboard/DataCoverage.tsx) · [Analytics operations and sync lag](../operations/admin-analytics.md)
- Use readable units and direct labels, reduce tick density on narrow screens, and distinguish series by stroke pattern or labels as well as color. Put a brief text summary and a labeled data table near the plot. Test at narrow viewport widths and high zoom, by keyboard, with a screen reader, and on touch. For interactive details, expose the same information on focus and touch and make hover or focus content dismissible, hoverable, and persistent where WCAG requires it. ## Sequence for the follow-up

Repair report coordination before judging a new layout. The current freshness checks run in GitHub Actions, whose scheduled runs can be delayed or dropped. During this investigation, the latest scheduled run started at 03:31 UTC and a later deployment-triggered run at 03:38 UTC, both successful; neither establishes a dependable five-minute cadence. The checks produce coverage evidence, independently of browser event collection. A missed check must not be described as proof that every visitor was lost. Review whether recorded traffic should remain queryable with explicit coverage warnings when this evidence lags, or whether the existing strict gate needs a more dependable runner. This is a proposed reporting design decision, not an implemented change. [Observer workflow](../../.github/workflows/analytics-observers.yml) · [Latest scheduled run inspected](https://github.com/sneakereco/solesneakers/actions/runs/46103251850) · [GitHub schedule behavior](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)
